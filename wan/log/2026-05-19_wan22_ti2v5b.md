TI2V 关键训练/推理逻辑：

- Wan2.2 VAE 使用 `WanVideoVAE38` / `Wan2.2_VAE.pth`，latent channel 从 2.1 的 16 变成 48，空间压缩 factor 为 16。
- 第一帧视频 latent 被写入 `latents[:, :, 0:1]`，不走额外 image encoder。
- separated timestep：第一帧 latent tokens 的 timestep 固定为 0，其余 latent frame tokens 使用 denoising timestep。
- loss 排除第一 latent frame，只对 `pred[:, :, 1:]` 和 `target[:, :, 1:]` 计算。

### 失败与修复记录

- job `183117`: 8GPU 申请 `PENDING (QOSMaxGRESPerUser)`，取消。
- job `183120`: 4GPU + repeated official shard load，在 dgx-043 上长时间卡住，取消；后续组合 smoke 改为 random-init 5B shape。
- job `183124`: TP2/CP2 先过，TP2+SP 失败于 RoPE freq shape。原因是 q/k 在当前 Wan RMSNorm 设计下经 ColumnParallel `gather_output=True` 回到 full hidden/full local sequence，SP 后不应再把 RoPE freqs 按 TP 切分。修复：RoPE freqs 只按 CP 切，不按 SP 切。
- job `183127`: TP2/CP2/TP2+SP/PP2 通过，PP2+CP2 报 PP payload shape mismatch。原因是 MCore pipeline schedule 会将 `--seq-length` 再除以 CP/SP；Wan PP payload 已是 local packed seq。修复：`overfit.sh` 在 `PP && (CP/SP)` 下把传给 Megatron 的 logical `SEQ_LENGTH` 乘回 `CP_SIZE * TP_SIZE(if SP)`，让 MCore 接收 shape 等于 Wan local payload。
- job `183128`: PP2+CP2 不再显式 shape error，但 stage0 idle、stage1 100% 长时间不出 iteration；同时旧 CP2 grad norm 为 `0.000`。原因是裸 `dist.all_gather` 不是 Megatron autograd CP primitive，forward 可跑但 cut gradient。修复：CP K/V gather 和 output gather 改用 `gather_from_sequence_parallel_region(..., group=cp_group)`；attention gather 用 `tensor_parallel_output_grad=True`，最终 duplicated loss gather 用 `False`；timestep/noise/context dropout 随机性在 CP 维度同步。

## 128 卡 seqlen 估算

当前样本 token 计算：

```text
latent frames = 13
latent H/W = 24/32
patch size = (1,2,2)
video tokens = 13 * 12 * 16 = 2496
```

推荐两档：

1. **Balanced training**: `TP2 + PP2 + CP16 + DP2 = 128`。相对已验证的 `TP2+PP2+CP2(+SP)`，CP 从 2 扩到 16，保守按 local query token 不变估算支持 `2496 * 8 = 19968` video tokens。
2. **Max sequence / no DP**: `TP2 + PP2 + CP32 + DP1 = 128`。估算支持 `2496 * 16 = 39936` video tokens。

换算成常见分辨率/帧数：

```text
19968 tokens:
  512x384  -> spatial tokens 192 -> ~104 latent frames -> ~413 raw frames -> 34.4s @12fps
  832x480  -> spatial tokens 390 -> ~51 latent frames  -> ~201 raw frames -> 16.8s @12fps
  1280x704 -> spatial tokens 880 -> ~22 latent frames  -> ~85 raw frames  -> 7.1s @12fps

39936 tokens:
  512x384  -> ~208 latent frames -> ~829 raw frames -> 69.1s @12fps
  832x480  -> ~102 latent frames -> ~405 raw frames -> 33.8s @12fps
  1280x704 -> ~45 latent frames  -> ~177 raw frames -> 14.8s @12fps
```

风险：

- 这是从 8GPU 矩阵外推，不是 128 卡长序列实测。
- 当前 CP 实现为了保持官方 attention 语义，会 gather full K/V；长序列下显存大概率能承受，但通信和 attention compute 会快速成为瓶颈。
- Wan2.2 5B 有 30 个 DiT blocks，`PP2` 正好 15 层/stage；不建议直接用不能整除 30 的 PP size，除非先补 virtual pipeline/uneven layer split 验证。
- SP 在短序列上变慢；长序列可作为显存保险开关，但不要默认认为它提升速度。
